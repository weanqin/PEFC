# result/ 正式结果目录写入门（硬规约）

> 用户 2026-10-30 指令建立（任务 `10-29-result-dir-policy`）。本规约为硬门：任何 agent 会话
> 在向 `result/` 写入前必须核对本文；目录内 `result/README.md` 为自描述副本。

## 目录用途

`/root/npi/result/` 只存放**最终用于论文写作的结果数据**（正式交付物）。

## 写入许可（必须满足其一，二选一）

1. **用户明确指令存入**——指令须点名 result 目录（例："请你将此次结果存放到 result 目录中"）；
2. **Agent 主动询问，且用户明确同意**（询问须在写入动作之前完成，同意须落在当轮对话或 consent 记录）。

除上述两种情形外，**任何文件不得写入 `result/`**——包括但不限于：训练/评估的常规落盘、
后台任务默认输出、汇总便利性复制、图表自动保存。

## 禁止与分流

- **中间结果 / 非正式结果**一律落 `outputs/<任务目录>/`（path-isolation / artifacts-management
  规约不变），禁止因"顺手"或"看起来是最终"而混入 `result/`；
- 是否"最终用于论文"由**用户**判定，agent 不得自行认定后直接写入——自行认定时只能走
  许可情形 2（主动询问）。

## 存入时的随档登记

每次存入须同步登记（放 `result/` 内清单文件或对应任务 summary）：

- 来源任务（`.trellis/tasks/<task>/`）与产物原始路径（`outputs/...`）；
- 生成时间与口径摘要（模型 ckpt、EC/GC 口径、被试集）——保证论文数字可溯源；
- 存入后**不就地修改**；更新 = 新版本文件并排 + 登记（对齐 path-isolation「已定版不动」）。

## 检查点挂钩

- **Quality Check** 新增一项：本轮是否向 `result/` 写入？若写入，许可情形（1 或 2）与同意
  证据是否可查证；不可查证 = 违规，须回滚并登记。
- 本规约与 `workflow-hard-gates.md`（无任务拦写码 / consent 门 / Stop 收尾校验）同层级执行。
