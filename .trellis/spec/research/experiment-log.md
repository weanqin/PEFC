# 实验日志规范

**一次实验** = 一次跑批 / 训练 / 评估 / 统计分析。每次实验对应一个 Run 块，四要素缺一不可。

## 文件位置

- **任务内**：`{TASK_DIR}/experiment.md`。`task.py create` 时由 `config.yaml` 的 `hooks.after_create` 自动播种模板；此后**追加式**记录，不删旧块。
- **长期沉淀**：任务归档前，把有长期对比价值的实验提炼为长期实验笔记（默认目录 `experiments/`；实际目录与命名惯例在初始化时确认，记录于 `.trellis/research/context.md` 文档地图），并在 `.trellis/research/progress.md` 里程碑区追加一行。纯过程性 Run 不必外提。

## Run 块四要素（硬性）

1. **目的与假设**：要回答什么问题 / 验证什么假设。禁止「跑一下看看」。
2. **配置**：
   - 代码位置：变体目录 + 版本标识（git 仓库写 commit/branch；非 git 仓库写文件名/日期快照）
   - 参数：与默认不同的超参、阈值、seed 必须全部列出
   - 环境：env 名 @ 机器（对照 `.trellis/research/environment.md`，写明本地/远程）
   - 数据：输入路径 + 筛选口径（如 manifest `qc_pass` 过滤、分组口径）
   - 命令：可复现的启动命令
3. **结果**：指标数字（不写「还行」「变好了」，写数值）+ 产物/图表路径（必须在本变体目录内）。
4. **结论**：支持 / 证伪 / 不确定 + 一句话依据；派生出的新问题或决策项同步到 `.trellis/research/progress.md`「当前状态 → 待拍板」。

## 时机

- **跑前**：先写「目的 + 配置」再启动（长跑/远程任务尤其如此，防止跑完忘配置）。
- **跑后**：同一会话内补齐「结果 + 结论」，不得留空块过夜。
- **归档前**：workflow 3.3 检查无空 Run 块，否则不得进入收尾。

## 对比与回溯

- 与既往实验对比时写明对照 Run 的编号/日期；指标口径必须一致，口径变化须单独声明并说明不可直接比较的部分。
- 「同配置重跑」也是一次 Run（记录两次的偏差），用于区分随机波动与真实差异。
- 结论被后续实验推翻时，不修改旧 Run 块，在新 Run 的结论里注明推翻关系。
